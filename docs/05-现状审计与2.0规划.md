## 一、产品现状概览

### 1. 核心定位与目标用户
- **定位**：围绕 `DouK-Downloader.exe`（cx_Freeze 控制台程序，Web API 端口 `5555`）外挂 Web 壳的**本地抖音博主媒体作品库与后处理工作台（星图画廊 / DouK-Lite）**。
- **目标用户**：Windows 11 个人重度收藏用户（追更博主、收集图集/视频/实况、需将抖音实况导入 iPhone、需从视频逐帧截取高清 PNG，偏好零命令行桌面体验）。

### 2. 已实现能力全景
- **启动与生命周期**：`星图画廊.vbs` 无窗启动 → `scripts/启动.cmd` 拉起上游 `5555` 与本机 `8765` → Chrome `--app` 独立窗口打开 → `build.txt` 版本比对热重启 → SSE 保活关窗自动退出（有下载/实况任务时不误杀）。
- **解析与下载**：单作品/博主主页双模式、分享文案自动提取清洗、发布/收藏双页签、日期窗+游标分段全量爬取（缩窗重试/置顶剔除/每段落盘/断点续爬/随时取消）、快速 30 天解析、解析清单预标「已存在」与「只选未下载」、1–6 线程并发下载、图片 `~tplv-` 去模板高清源探测、`.part` 文件头魔数嗅探扩展名、按静图/`实况\`/`视频\` 自动分流、历史误放整理。
- **画廊与浏览**：免索引扫描归组、全局统计与博主卡片墙、跨博主混排流（类型/博主/搜索/4 维排序/分页）、本地缩略图 LRU 缓存（300MB / 5000 文件）、查看器（大图/HEIC 实时转预览/HTTP Range 视频拖动/内置逐帧条/回收站安全删除）。
- **工具与截帧**：抖音实况一键转 iPhone Live Photo（HEIC + ≤3s MOV，写入 Apple MakerNote `0x0011` 与 `QuickTime:ContentIdentifier`）+ 独立专业逐帧截帧页（FPS 自动探测、胶片缩略图条、剪辑快捷键、Canvas 原分辨率 PNG 落盘、`ffmpeg` 兜底抽帧）。

### 3. 数据存储与实测规模（截至 2026-11-19）
- **上游体系（`Volume\`）**：
  - `Volume/settings.json`：含 `cookie`（字典结构）与 `original_quality` 等上游设置。
  - `Volume/DouK-Downloader.db`：上游 SQLite（`download_data` 615 行、`mapping_data` 5 行、`config_data` 3 行、`option_data` 1 行）；`DouK-Lite` 不直接读写该库。
  - 早期历史文件：`Volume/LivePhotos/`（272 个文件，102.5 MB）、`LivePhotos_台账.csv`（136 组记录）及 5 个 `UID*` 博主目录。
- **DouK-Lite 体系**：
  - `DouK-Lite/config.json`：当前指向 `E:\Files\pics`、`folder_template: "{nickname}"`。
  - `DouK-Lite/cache/creators.json`：8 位博主记录。
  - `DouK-Lite/cache/accounts/*.json`：8 份主页解析缓存（最大单号 1,066 条，7 份完整、1 份未完整）。
  - `DouK-Lite/cache/thumbs/`：2,749 张缩略图（约 32.61 MB）。
  - 当前媒体库（`E:\Files\pics`）：10 个内容目录 + `LivePhotos`（147 文件 / `_index.json` 73 条）+ `截帧`（63 文件），合计约 6,556 个文件、28.3 GB。

## 二、技术架构审计与已落地优化

### 1. 已在 `2026-11-19.1` 修复的严重/明确问题
1. **Cookie 字典传递失效**：`downloader.py` 原要求 `cookie` 为 `str`，遇到 `settings.json` 中的 `dict` 会静默置空。已在 `config.py` 新增 `cookie_header()` 统一转换字典/字符串并在下载器接入。
2. **解析/实况列表 300 条硬截断**：移除 `app.js` 300 条上限，改为分批加载更多；后端 `/api/works/items` 预标 `exists`（并兼容早期 `HH.MM.SS` 命名），前端新增「全部 / 未下载 / 已存在」筛选与「只选未下载」按钮。
3. **视频扫描无序截断**：`scan_frame_videos()` 与 `scan_live()` 不再在 `os.walk` 中途 `break`，改为全量收集按 `mtime` 降序排列后再按需切片（默认不截断）。
4. **查看器 `<video>` 连接泄漏**：`app.js` 切换与关闭查看器时显式执行 `pause()` + `removeAttribute("src")` + `load()` 释放 Range 流占用。
5. **前后端 `root` 传参不一致**：`config.py` 新增 `resolve_root()`，统一 `/api/livephoto/*`、`/api/frame*` 接口对前端 `root` 参数的处理。
6. **高频读盘与写放大**：`load_config()` / `read_app_settings()` 增加 `(mtime_ns, size)` 进程内缓存；`/api/post/delete` 改为仅失效受影响博主目录的 `_lib_cache`；`run_live_job` 批量合并刷盘 `_index.json`。
7. **任务并发安全与日志缺失**：`state.py` 补充加锁的任务读写/快照/取消接口；`config.py` 新增写往 `logs/app.log` 的 UTF-8 轮转日志器，`http_server.py` 启动重配 `stdout/stderr` 为 UTF-8。

### 2. 仍需在后续演进中解决的技术债务
1. **无本地数据库索引**：全量 `rglob("*")` 与内存排序在数万级文件后会成为明显延迟瓶颈；`aweme_id`、完整标题、标签等元数据未持久化，修改模板或博主改名易导致文件夹分裂与重复下载；`creators.json` 放在程序目录内导致切换保存路径后状态混用。
2. **远程封面链接过期**：`creators.json` 中的 `cover` 含 `x-expires` 签名，未下载本地作品的博主长期放置后头像/封面会失效。
3. **前端单文件膨胀**：`web/app.js` 已超 3,000 行，查看器 `VFR` 与独立截帧页 `FX` 存在部分状态逻辑重复，建议 2.0 前按原生 ES Modules 拆模块。
4. **解析取消残留连接**：`_post_cancellable` 取消时子线程仍等待上游 HTTP 超时释放；`quit_watch` 关窗 6 秒强杀不保护在途解析任务。
5. **上游边界不确定性**：因未反编译 `DouK-Downloader.exe` 内部 `lib/src/*.pyc`，上游 `/douyin/mix`（合集）接口细节及 `taskkill /F` 对上游 SQLite 写入瞬间的影响仍需实机/文档核对。

### 推荐 2.0 版本路线图
- **v2.0 Alpha（索引与地基）**：拆分 `app.js` 为原生 ES Modules；落地 `<root>/.douk-gallery.db` 增量同步索引，打通 `aweme_id` 去重与跨路径隔离。
- **v2.0 Beta（追更与效率）**：上线「全量博主一键追更」串行队列、线上缺失/删帖抢救状态对比、Cookie 失效检测与弹窗可视化更新（并核对接入合集/多链接排队）。
- **v2.0 Release（资产与工作流闭环）**：上线作品星标/标签专辑、画廊多选批量操作、图集查看器缩略图条、LivePhotos 成品库批次导出与已导入标记、截帧页 `ffmpeg` 精准抽帧及截帧成品库。
- **v2.1+（维护与智能扩展）**：空间体积分析与查重清理、模板迁移与备份快照；按需提供离线以图搜图/语义检索插件。

### 明确不值得开发的方向
1. **自研替代 `DouK-Downloader.exe` 的抖音签名与逆向逻辑**：维护代价极高，应继续复用上游内核。
2. **云端大模型（LLM/VLM）生成文案或对话找图**：外发隐私媒体风险高、有持续费用、对个人找图不如标签与本地检索实用。
3. **内置复杂多轨视频剪辑/滤镜调色器**：偏离作品库定位，应交由专业剪辑软件处理。
4. **公网暴露 / 多用户账号 / 远程同步服务端**：当前为本机可信单人伴侣架构，公网化引入重大安全与鉴权成本。
5. **7×24 后台无人值守高频轮询**：极易触发抖音账号风控或验证码封禁，不如手动点击一键追更安全。
6. **强行实现非官方无线/私有协议直传 iPhone**：协议脆弱易失效，继续做好批次导出配合爱思助手 / iCloud 更稳定。
